# INT-005 admin operations acceptance

Date: 2026-07-19

Platform: Windows 11 10.0.26100 x64, Node.js 22.17.0, pnpm 11.13.1,
Python 3.13.13 (uv), FastAPI through Starlette `TestClient`, and PostgreSQL 16
through the local docker-compose `postgres` service.

Status: **DONE**. The protected admin surfaces now consume generated API
clients instead of renderer fixtures, preserve SPA authentication while
navigating, propagate the real health projection into the shared sidebar, and
keep read, replay, provider, audit, backup, and restore operations scoped,
redacted, confirmed, idempotent, and auditable.

## Integrated acceptance claim

The gate verifies these boundaries across the Admin renderer, generated client,
FastAPI routes, and PostgreSQL formal state:

1. Student tokens cannot enter the independent Admin guard or read admin API
   projections. Course/system administrators see only their tenant, with stable
   pagination and no password fields.
2. Student detail, progress, evidence, pending registrations, resource review
   evidence, Agent replay, provider configuration, health, metrics, logs,
   database status, and immutable audit history are loaded from protected APIs.
3. Agent input snapshots, provider secrets, operational-log context, and audit
   detail are redacted before they cross the API boundary. Provider
   connectivity checks never return stored key material.
4. Backup and restore require explicit confirmation plus an idempotency key.
   Replays return the original operation, failed restore details remain
   redacted, and every maintenance transition is audited.
5. Maintenance cannot insert, update, or delete `MasteryState` rows. The
   acceptance test compares the formal mastery projection before and after
   backup, successful restore, replay, cancellation, and failed restore paths.
6. Shared `AppShell` links use router navigation. A health-page result updates
   the sidebar once through `onHealthChange` and remains visible after an SPA
   route transition, without an independent global health fetch.

## Real-browser evidence

A headed Chromium session used the Admin Vite application at loopback port
5173 and a local FastAPI process at loopback port 8001. The disposable database
was migrated through Alembic head and seeded by
`scripts/acceptance/admin-int005-fixture.py`; no production credential was
read or used.

Observed material results:

- the generated login endpoint returned 200 and `/auth/me` established the
  system-administrator session;
- the overview and protected operational routes loaded through the SPA;
- `/admin/health` rendered API/PostgreSQL healthy and Worker, sandbox, Redis,
  and object-store degraded from the real probes;
- the shared sidebar changed from “正在检查系统状态” to “系统存在降级 / 4
  个组件需要关注”;
- navigating from Health to Resource Review preserved the same sidebar status,
  proving the HealthPage-to-layout callback survives SPA navigation;
- resource review remained read-only and loaded from the protected API.

React development StrictMode issued the Health-page effect twice, producing
two successful health requests; there was no separate layout/global health
request. An earlier login attempt failed while Docker Desktop restarted the
PostgreSQL container. After the container returned healthy, the unchanged UI
and API completed the same login successfully. The corresponding CORS/fetch
console entries belong to that interrupted request; the only unrelated browser
error was a missing development favicon.

The Playwright session, local API/Vite processes, and its worktree-local trace
files were removed. The exact disposable database
`pymentor_int005_browser_resume_20260719` was force-dropped and verified absent
after the browser run.

## Red/Green notes

The first full Admin test after adding a layout-level health request exposed a
duplicate authorization/fetch path. The implementation was refactored so only
`HealthPage` owns the request and reports its normalized projection to
`AdminLayout`; all 17 Admin tests and the final real-browser replay then passed.
The shared AppShell router callback was applied to both Admin and Student
renderers, and the 6 shared-UI plus 40 Student tests protect that regression.

## Commands not run and residual risk

- A live AI provider connectivity request was not run because no provider
  credential is available or required. The protected connectivity endpoint was
  verified with a deterministic connector and confirmed not to reveal keys.
- A production object-store backup/restore was not run. Artifact I/O is tested
  through the bounded maintenance port while operation state, confirmation,
  idempotency, audit, failure, and mastery safety use real PostgreSQL. Live
  deployment smoke belongs to INT-007.
- Destructive student reset/delete is not exposed by the integrated backend
  contract, so the renderer does not invent it. The acceptance gate covers the
  implemented backup/restore maintenance commands and proves they cannot
  rewrite mastery.
- This evidence does not authorize publishing or claim signed-release
  readiness; those conclusions are reserved for INT-007 and the final audit.
